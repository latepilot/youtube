# vinyl-spin

Редактор и рендерер YouTube-роликов «вращающаяся пластинка» на замену шаблону из Final Cut Pro X.
В кадре три слоя: фон (медленный зум на всю длину ролика и плёночное зерно), диск с картинкой и дыркой
(33⅓ об/мин по часовой) и логотип в правом нижнем углу.

- `index.html`: редактор пластинки. Открывается с диска в Chrome, без сборки и без интернета.
- `viz.html`: визуализация под конкретный трек (тема «даб-техно»): графика в стиле научных приборов реагирует
  на кик, хэты, аккорды и их эхо, брейки и дропы. Вкладка «Визуализация трека» в том же окне.
- `vinyl-spin.command` + `studio.mjs`: запуск двойным кликом, рендер кнопкой прямо из редактора.
- `render.mjs`: рендер полного ролика под длину аудио из командной строки.
- `lib.mjs`: общая часть (ffmpeg, звук без потерь, проверки). Кадры рисует тот же `index.html`, поэтому превью и ролик совпадают.
- `test.mjs`: проверки пластинки (детерминизм, звук бит-в-бит во всех форматах, WebCodecs, скорость).
- `test-viz.mjs` + `tools/dubtechno-track.mjs`: проверки визуализации на синтетическом даб-техно треке с точной разметкой.
- `docs/`: ТЗ, handoff и кадр-образец.

## Как это устроено

Кадр задаётся чистой функцией времени `seek(t)` на WebGL2: зум фона `s(t)` от «масштаба в начале» до «масштаба в конце»
за всю длительность аудио, зерно из целочисленного хэша (номер кадра + seed, без `Math.random`), поворот диска
`2π · об/мин / 60 · t` (угол считается в double и сворачивается по 2π, чтобы на часе ролика не было дрожи). Кадр N
можно нарисовать, не считая предыдущие, и два рендера дают одинаковые пиксели.

Экспорт идёт одним из двух путей, кадры в них одинаковые:

1. **WebCodecs** (основной, на маке): браузер упаковывает кадр в I420 (BT.709) прямо на GPU и сам кодирует H.264
   (на M-чипах через VideoToolbox). Готовый поток уходит в ffmpeg с `-c:v copy`, то есть видео не перекодируется второй раз.
2. **Сырые кадры в ffmpeg** (запасной): тот же I420 уходит в ffmpeg, который кодирует через `h264_videotoolbox`
   (мак) или `libx264`.

**Звук не перекодируется с потерями.** WAV/AIFF копируются как есть в `.mov`, FLAC/ALAC раскрываются в PCM той же
разрядности и частоты, MP3/AAC копируются пакетами. После рендера `render.mjs` декодирует звук исходника и ролика
и сравнивает md5. Громкость не трогается; LUFS и true peak выводятся только для справки.

## Запуск на маке без командной строки

Один раз нужны Node.js (https://nodejs.org) и ffmpeg (у тебя уже есть). `npm install` для этого способа не нужен.

1. Двойной клик по **`vinyl-spin.command`** в папке `vinyl-spin`. Откроется окно Терминала (это журнал, печатать
   в нём ничего не надо) и редактор в Google Chrome.
2. Перетащи фон, диск и аудио (логотип стандартный, его можно заменить). Подкрути параметры.
3. В блоке «Рендер ролика» выбери «весь ролик» (или 20 с для проверки) и нажми **«Рендер ролика»**.
   Прогресс и оставшееся время видны там же, есть «Отменить».
4. Готовый ролик окажется в `~/Movies/vinyl-spin/`, кнопка «Показать в Finder» откроет его. Под ней отчёт:
   число кадров и проверка звука бит-в-бит.

Кадры рисует и кодирует тот же Chrome (H.264 на видеокарте через WebCodecs), а `studio.mjs` принимает поток и
собирает ролик в ffmpeg со звуком без потерь. Если в этом Chrome нет H.264, кадры кодирует ffmpeg (`h264_videotoolbox`).
Вкладку во время рендера не закрывай. Окно Терминала закрывай, когда закончишь.

Если macOS не даёт открыть файл («неустановленный разработчик»): правый клик → «Открыть» → «Открыть», один раз.
Если пишет «нет прав», один раз выполни `chmod +x vinyl-spin.command`. Файл можно перетащить в Dock (правая часть, рядом с корзиной).

## Визуализация трека (даб-техно)

Открой вкладку **«Визуализация трека»** (или `viz.html`), перетащи трек. Через несколько секунд под картинкой появится
карта трека: секции (интро, грув, брейк, аутро, ▲ — дроп), громкость низа/середины/верха и отметки ударов.
Клик по карте — перейти туда. Кнопка «⇥ секция» прыгает к следующей секции (за два такта до неё).

Что слышит анализ (всё в браузере, детерминированно, повторный анализ того же файла даёт ту же карту):

| В звуке | Как находится | Что делает картинка |
|---|---|---|
| Кик | атака в полосе 30–150 Гц на доле сетки | синие пятна набухают, белая планка растёт, расходятся синие кольца, силовые линии прогибаются |
| Аккорд и его эхо | атака 300–2500 Гц, звучит дольше 40 мс; эхо — затухающая цепочка | красные пятна, расходящиеся контуры и белые серпы — по одному на каждое эхо |
| Хэты | атака выше 6 кГц, звенит дольше пары мс | пиксельная вспышка-крест, зажигаются точки сетки и квадраты легенды |
| Громкость полос | огибающие низа, середины и верха | живая «волна» трека (6 с вокруг текущего момента): в «листе» — тонкий пиксельный контур одним цветом, как на экране Elektron Digitakt (внешний — вся громкость, пунктир — низ) |
| Секции | есть кик / нет кика + резкие изменения громкости полос по тактам | на брейках больше ASCII, в грувах меньше; сцены от секций не зависят |
| Дроп (кик вернулся) | граница «без кика → с киком» | перед ним всё дышит в такт долям, на нём глитч, ударная волна из центра и быстрое перетекание в новую сцену |
| Сильный аккорд | начало цепочки эха | короткий глитч: полосы кадра съезжают, блоки повторяют соседей |
| Верх и хэты | огибающая выше 6 кГц | больше ASCII в кадре, символы перебираются быстрее |

Слов в кадре нет. Четыре сцены по мотивам референсов: «три прибора» и «кольца и волна» (тёмные),
«лист с волной» и «поле» (светлые). Стиль меняется сам, без привязки к секциям: каждые 3–6 секунд
(«Смена стиля: не чаще / не реже, чем раз в, с»; граница ставится на ближайшую долю, на дропе смена обязательна)
к случайной другой сцене. Сцены не склеиваются, а перетекают («Перетекание стилей, с»): новая проступает
пиксельными блоками волной слева направо, по краю фронта — цветные блоки, глитч и россыпь ASCII.
В «Сценах» можно оставить одну — тогда меняются только её вариант и ASCII.

ASCII у каждого отрезка стиля свой: полосы, меняющиеся на каждой доле; бегущие волны; «дождь» столбцами;
круги от центра (толкаются киком); или их сочетания. Символы всё время перебираются (разные знаки и цифры,
плотнее там, где картинка ярче), по ним бежит перелив синий → красный → золотой и волна яркости.
Ещё у каждого отрезка может быть свой эффект («Эффекты стиля»): зеркало (симметрия по вертикали),
1-битный дизеринг крупным пикселем, растр круглыми точками под 45°, волна строк (качается от низа),
или их сочетания; часть отрезков идёт чистыми. На аккордах яркое тянется шлейфами по строкам,
на ударе аккорда и на дропе выворачиваются несколько блоков (это часть «Глитча»).

Цветовая схема плавно меняется («Цветовая схема» → «плавно меняется», период — «Смена схемы: каждые, с»):
первая схема — синий, красный и золотой из панели, дальше по кругу ещё семь (бирюза/розовый/лайм, голубой/фиолетовый,
огонь, фиолетовый/маджента, кислотный, бирюза/оранжевый, белый/красный); схема держится чуть больше половины
периода, потом за оставшееся время перетекает в следующую. «Не меняется» — всё время цвета из панели.

Кадр всё время слегка дышит (зум и наклон от низа), поверх сцены — спектр-полоска истории трека и бегущая
метка такта. Хроматическая аберрация разводит каналы к краям кадра и усиливается на кик. Силу ASCII, глитча
и аберрации можно убавить до нуля в панели. Синий, красный и золотой, размер «пикселя» пятен и зерно тоже
меняются. Всё сохраняется в пресет `.viz.json` вместе с картой трека.

Если анализ ошибся: «Сетка и видео» → «Темп вручную» и «Сдвиг сетки долей»; если картинка чуть опаздывает
или спешит относительно звука — «Реакция на трек» → «Сдвиг картинки, мс».

Рендер — та же кнопка «Рендер ролика», что у пластинки (нужен запуск через `vinyl-spin.command`), звук без потерь.

## Запуск из командной строки (пакетно, по пресету)

```bash
cd vinyl-spin
npm install                      # ставит Playwright; браузер не качает, берёт твой Google Chrome
node render.mjs --preset ~/Movies/выпуск/preset.json            # файлы берутся из пресета, рядом с ним
node render.mjs --preset preset.json --bg фон.jpg --disk диск.png --audio микс.wav --out ролик.mov
node render.mjs --preset preset.json --limit 20                  # первые 20 с для проверки
node render.mjs --preset preset.json --from -20 --limit 20       # последние 20 с (зум в конце)
node render.mjs --preset preset.json --frame 3000 --png кадр.png # один кадр в PNG
node render.mjs --preset preset.json --logo другой.png           # свой логотип
node render.mjs --preset preset.json --logo ""                   # без логотипа
node render.mjs --help
```

Если в выводе `GPU браузера` написано SwiftShader, значит, Chrome без окна не получил видеокарту. Тогда добавь `--headed`.

## Что проверить на маке

```bash
node test.mjs               # всё: исходники, детерминизм, звук во всех форматах, WebCodecs H.264, скорость
node test.mjs speed         # только скорость: 60 с 1080p25 через WebCodecs и через videotoolbox
VS_SPEED_SEC=300 node test.mjs speed   # замер подольше
```

```bash
node test-viz.mjs           # визуализация: точность анализа на эталонном треке, детерминизм кадра, рендер через студию
node test-viz.mjs frames    # кадры по секциям в out/test/viz-*.png
```

Тестовые файлы и результаты складываются в `out/test/`, эта папка в git не попадает.

## Параметры по умолчанию (замеры с кадра-образца)

| | |
|---|---|
| Диск | 90 % высоты кадра, по центру, 33⅓ об/мин по часовой, без размытия движения |
| Дырка | 7,3 % диаметра диска, заливка #C0C0C0 с зерном (есть режим «прозрачная») |
| Логотип | стандартный KËNIG FLOW (вшит в `index.html`, оригинал `assets/logo.jpg`), 13,1 % высоты, отступ 4,2 % справа и 4,0 % снизу |
| Зерно | монохромное, размер 2,5 px (при 1080p), СКО 6,5 %, только на фоне и в дырке |
| Зум | 1,00 → 1,15 линейно за всю длину. **Это не замер, а заглушка** (см. вопросы в handoff.md §5) |
| Фон | можно перевести в ч/б («Фон и зум» → «Фон в ч/б») |
| Видео | 1080p, 25 fps (есть 24/30/50/60), H.264 High, 25 Мбит/с, ключевой кадр каждые 0,5 с |

# Шаблон «вращающаяся пластинка» для YouTube — HTML-редактор

Бриф для новой сессии Claude Code. Составлен 2026-09-28. Цель: разработать один HTML-файл, который заменяет мой шаблон из Final Cut Pro X и не зависит ни от FCPX, ни от DaVinci.

**Как пользоваться этим файлом.** Открой новую сессию в папке проекта (предложение: `~/CODE/Background generators/vinyl-spin/`, рядом с остальными генераторами), скажи: «прочитай `~/Desktop/Vinyl-spin-video-template.md` и начинай с фазы 0». Отвечай на «ты», по-русски.

## 1. Что это и зачем

Я делаю музыку (проект **Prostye Tona**, эксперимент/электроника/даб-техно) и миксы (**D.Andry**, минимал/дип-хаус/техно) и выкладываю их на YouTube в виде статичных роликов: на экране **фон**, а по центру **круг-«пластинка» с картинкой и дыркой**, который вращается, как виниловый диск. Фон медленно приближается.

Сейчас это делается в **Final Cut Pro X по шаблону**: в нём можно заменить фон и картинку на пластинке. Хочу **то же самое в одном HTML-файле**: загрузил фон, загрузил картинку диска, подкрутил параметры, увидел живое превью, нажал экспорт и получил готовый ролик (или зацикленный клип, который растягивается под длину микса).

Что это даёт: независимость от FCPX, пакетное производство роликов (потом можно на каждый трек одним махом), пресеты на каждый выпуск, экспорт обложки/превью из того же кадра.

## 2. Как выглядит результат (по моим существующим роликам)

Видно на скриншоте YouTube-канала (треки Prostye Tona: Entropy 7:57, Mirai 13:31, Aquarius 14:42; миксы D.Andry: Kak nOstroenie? 44:55, Vecherok 1:00:58, Trip 52:58, Chase the Sun и др.):

- **Формат:** 16:9 (обложка ролика на канале).
- **Фон:** текстурный, зернистый. У Prostye Tona серый/чёрно-белый коллаж с бумажной фактурой, у D.Andry миксов яркий зелёный. Фон **медленно приближается** (эффект push-in).
- **Пластинка:** идеальный круг с картинкой внутри (фото, абстракция, обложка), по центру кадра, **маленькая дырка в центре**. Диск вращается непрерывно, картинка и нанесённый на неё текст (например, «ENTROPY», «AQUARIUS») поворачиваются вместе с диском.
- Картинку диска и фон можно менять независимо друг от друга.

> ⚠️ Точные значения (скорость вращения, размер диска и дырки, кривая и величина приближения, наличие тени/бликов/зерна поверх диска) **я не знаю наверняка, их надо снять с реального FCPX-шаблона** (см. фазу 0). Не угадывать: сначала спросить меня или получить скриншоты/экспорт из FCPX.

## 3. Подход: чистая функция времени `seek(t)`

Ядро — та же идея, что в курсе по motion-видео из кода (см. раздел 8): вся картинка это **чистая функция времени**. Функция `window.seek(t)` рисует точный кадр для любого момента `t`, без таймеров, CSS-переходов, `Math.random` и состояния между кадрами (шум для зерна только seeded).

Почему так:
- Превью в браузере и итоговый рендер выглядят **один в один**.
- Рендер детерминирован: два прогона дают одинаковые кадры.
- Кадр 812 можно нарисовать, не считая кадры 0…811 (важно для быстрой перемотки в превью и для рендера кусками).
- Зацикливание считается математически, а не «на глаз».

Вне рендера (когда `!navigator.webdriver`) — живой цикл `requestAnimationFrame` с `seek(t % длительность)` для превью.

## 4. Функциональные требования

**Ввод (всё drag-and-drop и кнопки «выбрать файл»):**
- фон: любое изображение (cover-fit, без искажений; параметры позиции/масштаба)
- картинка диска: любое изображение (кроп до квадрата → круг; смещение/масштаб внутри круга)
- опционально: аудио-файл (для превью синхронизации и для экспорта)

**Параметры (панель с бегунками, значения по умолчанию взять из FCPX-шаблона):**
- диск: диаметр (в % от высоты кадра), позиция (x, y), направление и скорость вращения (об/мин; 33⅓ как отправная точка, уточнить)
- дырка: диаметр (в % от диска), режим (прозрачная — виден фон; сплошной цвет; свой цвет)
- фон: величина приближения (масштаб от … до …), длительность цикла, кривая (ease), режим (бесконечное «дыхание» в обе стороны для зацикливания либо линейный push-in на всю длину)
- зерно/текстура поверх (интенсивность, размер; seeded, не Math.random)
- при необходимости: тень/блик/кромка диска (если есть в шаблоне)

**Вывод:**
- живое превью в браузере
- экспорт **кадра-обложки** PNG (например, 1280×720 для YouTube-превью)
- экспорт **ролика**: зацикленный клип (10–20 секунд) и/или ролик под длину аудио
- **пресеты**: сохранить/загрузить всё состояние в JSON (для каждого выпуска отдельный)

## 5. Зацикливание — главная техническая хитрость

Миксы длятся 45–60 минут. Рендерить час кадров не нужно: делаем **короткий зацикленный клип** и растягиваем под аудио.

Чтобы шов не был виден:
- длительность цикла `D` = целое число оборотов диска: `D = k · 60 / RPM` (при 33⅓ об/мин один оборот = 1,8 с)
- приближение фона должно возвращаться в начало: либо синусоидальное «дыхание» (in → out), либо push-in с плавным сведением к началу; **линейное приближение на всю длину микса зациклить нельзя** (потребует либо рендер всей длины, либо кусками)
- зерно/шум — на loop-периоде без скачка (seeded по `t mod D`)

Растягивание под звук (быстро, видео не перекодируется):
```bash
ffmpeg -stream_loop -1 -i loop.mp4 -i mix.wav -shortest -c:v copy -c:a aac -b:a 320k out.mp4
```
Проверить: нет ли видимого скачка на стыке, размер файла (зерно раздувает битрейт), нормально ли YouTube принимает такой файл.

## 6. Рендер

Отдельным шагом, как в курсе: Playwright + ffmpeg.

- `node render.mjs --fps 30|60 --dur 20 --sub 4 --w 1920 --h 1080`
- headless Chromium открывает `index.html`, вызывает `seek(t)` для каждого (под)кадра, скриншотит, отдаёт в ffmpeg
- вращающийся текстурный диск выигрывает от **motion blur** через субкадры (`tmix`), особенно на 60 fps; 4 субкадра быстрее, но дают «призраков» на быстрых движениях, 8 — качественнее и в ~2 раза дороже
- выход: H.264, `yuv420p`, CRF 16–20 (подобрать под размер файла)
- ориентир по времени: около 1–1,5 мин рендера на секунду ролика при 8 субкадрах — для 20-секундной петли это нормально

Позже (необязательно): кнопка «Экспорт» в самом HTML, которая через маленький локальный сервер запускает этот рендер, чтобы не нужен был терминал.
